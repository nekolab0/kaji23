# AdSense不承認（有用性の低いコンテンツ）への対応方針

- 決定日：2026-11-28
- 審査結果：不承認（有用性の低いコンテンツ）。ads.txtは承認済み
- 置き場所：docs/adsense-remediation.md（docs/decisions.md からリンクする）
- 自動改善エージェントは、作業前に STATUS.md とあわせてこのファイルを読むこと

## 1. 原因の見立て（2026-11-28時点のサイト確認より）

| # | 問題 | 具体例 | 重さ |
|---|---|---|---|
| 1 | 中身のない火事ページが自動で大量にできている | f-n-東京都-墨田区-京島-2026-11-27.html：固有の文は「〇月〇日、〇〇で火事が報道されました」の1文と、Google Newsリダイレクトへのリンク1本だけ。表示テキストの7〜8割がテンプレ | 最大 |
| 2 | 都道府県ページが見出しの並べ直しだけ | p-長野県.html：37件の「市名・日付・出典」だけで、地域の解説や傾向がない。上田市181件と出ているのに一覧に上田市がなく、数字が合わない | 大 |
| 3 | 報告欄がJavaScriptで後から読み込まれる | 審査ロボットには「いまの報告を読み込んでいます…」しか見えない | 中 |
| 4 | 読み物が少なく浅い | ガイド6本。g-cause.htmlは消防白書の数字の並べ直しが中心。更新日（11/08）と載っているデータ（11/27取得）が食い違う | 中 |
| 5 | 信頼性ページが弱い | お問い合わせページへの導線がない。運営者情報・規約・プライバシーが1ページ（policy.html）に同居 | 小〜中 |

E009（2026-11-18）で、90日より前の火事のページや記録のない市区町村・町（5,666ページ）にはすでに `noindex, follow` を付けている。残っている問題は、**直近90日の火事のページ**（1日数十件ずつ増える）の多くが、上の墨田区京島のように1文＋リンク1本のまま index になっていること。

Googleのスパムポリシーでいう「スクレイピング（外部の情報を寄せ集めて価値を足していない）」と「大量生成コンテンツ（scaled content abuse）」に、1と2が当たっていると見る。AdSenseはサイト全体で判定するため、良いページがあっても、薄いページが数百〜数千あると全体が「有用性が低い」と判定される。

## 2. 方針の変更（ここが本題）

**評価軸を「ページ数・件数」から「インデックスされたページ1枚あたりの価値」に変える。**

これまでの「取り込み件数はkaji.news以上に、可能な限り増やす」はデータの収集量としては続ける。ただし、収集した1件ごとにインデックス対象のページを作ることはやめる。データはたくさん集め、検索エンジンに見せるページは絞る。

## 3. やること（優先順）

### P0：再申請の前に必ず終わらせる

1. **薄い火事ページを noindex にする**
   - 個別の火事ページは、次の「インデックス条件」を1つ以上満たすときだけ index にする。満たさないものは `noindex,follow` にし、sitemap.xml から外す
     - 出典が2つ以上ある（報道＋消防発表など）
     - 口コミ・目撃報告が3件以上ある
     - 時系列（第一報→消防発表→鎮火など）が2段階以上ある
     - ニュースで大きく扱われた火事（死傷者あり、延焼、全国ニュースなど）
   - ページそのものは消さない（URLは残し、利用者は今までどおり見られる）
   - E009 の判定（12/2）と、SEO の変更は週1件の決まりがあるので、**実装は 12/2 の判定のあと**。SEO 担当（`.claude/agents/seo.md`）に条件の中身を確認させてから入れる。大量の index／noindex の切り替えなので運営者の承認制（下の5章）
2. **市区町村ページを主役にする**（薄い個別ページの受け皿）
   - 1ページに次を載せる：その地域の火事の時系列、直近30日・12か月の件数推移、多い時間帯や月、近い消防署と案内ダイヤルの番号、ハザードマップへのリンク、地域の過去の大きな火事
   - どれも火事速が自分で貯めたデータから作れるもので、ほかのサイトにはない
3. **報告欄を静的HTMLにも書き出す**
   - ビルド時点の直近の報告をHTMLに埋め込み、JavaScriptはその後の差分だけ更新する。報告が0件のときは「直近24時間、この地域の報告はありません（最終確認 〇時〇分）」と明示する
4. **報道元へのリンクを直接のURLにする**
   - Google Newsのリダイレクトではなく、報道元の記事URLを載せる（出典の信頼性が上がる）。RSS から元の URL が取れないものは、まず取れる方法があるか調べる（取れなければ今のまま）
5. **数字の不一致をなくす**
   - 件数表示と一覧の中身が合わないものを直す。自動チェック（6章）に組み込む
6. **信頼性ページを分ける**
   - 運営者情報（本名は出さない。運営の目的、運営体制、連絡先）／編集方針とデータの集め方／訂正・削除の依頼の受け方／お問い合わせ（contact@kajisoku.jp）／プライバシーポリシー／利用規約
   - 全ページのフッターから行けるようにする

### P1：再申請までに進めておく

7. **読み物を「火事速のデータでしか書けない記事」にする**
   - 例：「冬の火事は何時に多い？火事速の〇〇件から見た時間帯」「23区で火事の報告が多い町はどこ？」「サイレンが聞こえたときに確かめる手順」
   - 白書の数字の紹介だけで終わらせない。集計期間・件数・重複の除き方を記事内に明記する
   - 再申請時点で、こうした記事を15本以上にする（1本2,000字前後を目安に。量より、ほかで読めない中身を優先）
8. **更新日のルール**：本文を直したら更新日を変える。自動で変わるデータには「〇月〇日〇時取得」と別に書く
9. **週次まとめ・ランキングにも解説を1段落入れる**（その週の特徴、前週との違い）

### P2：続けること

10. 検索・SNS・ブックマークからの実際の訪問を増やす（審査には「ユーザーの関心」が含まれる）。Search Consoleで、インデックス数とクリック数を週ごとに見る

## 4. 再申請のタイミング

- P0がすべて終わり、P1の記事が15本以上になってから
- さらに、Search Consoleで noindex にしたページがインデックスから外れ始めたことを確認してから（目安：変更から2〜4週間）
- 急いで何度も出さない。直していないまま出しても同じ結果になる
- 再申請した日と結果は decisions.md に記録する

## 5. 自動改善のルール変更

| 項目 | これまで | これから |
|---|---|---|
| 新しい火事ページ | 収集したら自動で作成・公開 | 作成は自動。index にするかはインデックス条件で自動判定 |
| 新しい読み物記事 | 少数なら自動 | 自動のまま。ただし品質チェック（下）を通ったものだけ公開 |
| 一度に大量のページの index／noindex を切り替える | 決まりなし | 承認制（ユーザーに確認） |
| 成果の指標 | 件数・PV | インデックス数に対するクリック数、1ページあたりの滞在、PV |

### 公開前の品質チェック（検証役が必ず見る）

- そのページにしかない文・データが、テンプレ以外で300字以上ある（火事ページは時系列・出典・口コミで満たしてもよい）
- 表示している件数と一覧の中身が一致している
- 更新日と取得日時が食い違っていない
- 報道記事の文章を写していない（要約は自分の言葉で短く、出典を明記）
- 1ページの中で同じ数字や文を繰り返していない

## 6. AdSense の再申請までのつなぎ（忍者AdMax）

- 2026-11-28 に運営者が決定。審査のない忍者AdMax を、AdSense の `slot` が空のあいだだけ出す（`site/ads.json` の `admax.tag`。生成は `site/build.py` の `ADS_PROVIDER`）
- 位置は AdSense と同じ（区切りの間・1ページ2つまで・policy/rules/about/dial には出さない）。オーバーレイ・画面下固定・全画面・ポップアップの枠は作らない
- AdSense の `slot` が入れば、自動で AdSense に切り替わる（忍者AdMax のタグは出なくなる）
- AdSense の読み込みタグ（head）は審査のために残す。他社の広告を一緒に出すこと自体は AdSense の規約で禁止されていない。ただし、忍者AdMax の広告の中身が見苦しい（アダルト・過激）ものになる場合は、管理画面のフィルタで止める。再申請の前に、出ている広告の中身を運営者が一度見る
- 収益の目安は低い（クリック単価は AdSense より低いのが一般的）。ねらいは「広告の枠でどれくらい収益が出るか」を早めに知ること
