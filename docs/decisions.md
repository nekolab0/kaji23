## サイトの方針
- 日付不明：**サイトの目的は「近くで火事が起きたとき、どこで火事かを町単位でリアルタイムに確かめる場」。** 理由：区や町の統計データそのものは拡散されないため。主役は「いまの火事」。
- 日付不明：**全国版を本線にし、23区だけの版は `backup-23ku` ブランチに残す。**
- 日付不明：**常に kaji.news（火事どこ速報）より便利なサイトにする。取り込む火事の件数も kaji.news 以上にする。** 理由：やりたいことの大半を kaji.news が実現しているため、同じ内容を網羅したうえで差をつける。似たサイトが後から出ても超えられない参入障壁をつくる。
- 日付不明：**流入施策では、PV（広告収益）を近所の人の報告数より先に追う。**
- 日付不明：**広告は Google AdSense。ポップアップなど見やすさを下げる形式は載せず、ページの区切りの間にだけ出す。自動広告は使わない。**
- 日付不明：**運営者の本名はサイトに出さない。問い合わせ先は `contact@kajisoku.jp`。** 理由：本名を出したくないことと、広告の審査を考えてのこと。
- 日付不明：**デザインは背景白。**

## 情報源

- 日付不明：**報道は場所と日付などの事実だけを使い、見出し文は保存も表示もしない。**
- 日付不明：**東京消防庁の災害情報案内（03-3212-2119）には自動で電話しない。** 理由：人が応対する窓口だったため。23区は報道と利用者の報告を組み合わせる。
- 日付不明：**案内ダイヤルへの自動電話は、必要なときだけかける（一時保留から方針を変えて導入）。** 理由：件数を増やすため。費用を抑えるため、1日の上限と、同じ番号への間隔を設ける。

## 機能
- 日付不明：**町・市区町村ごとの Web プッシュ通知を導入する。**
- 2026-11-05（PR #1）：**町の固定ページは、火事の記録がある町だけ作る。** それ以外の町は `town.html?…` で表示し、サイトマップに載せない。理由：中身のないページを大量に作らないため。
- 2026-11-07（PR #7）：**`main` にマージしたらすぐ公開する。30分ごとの作り直しは、受付サーバーからも呼び出す。** 理由：GitHub の定期実行は混雑で数時間あくことがあるため。
- 2026-11-07・11-08（PR #12・#13）：**GitHub Pages の一時的な公開の失敗は、1分おいてもう一度試す。直近3時間に公開できていれば、エラーにしない。** 理由：GitHub 側の混雑でエラーのメールが届いていたため。
- 2026-11-10（PR #20）：**日本時間 2:37・3:07 の回は動かさない。** 理由：この時間帯は GitHub Pages の公開が毎晩詰まって失敗していたため。
- 2026-11-11（PR #21）：**本番の監視（受付サーバーの応答など）が失敗しても、サイトの公開は止めない。** 監視は別のジョブにして、失敗したときだけメールが届く。理由：本番の一時的な不調で公開が止まったため。

## 読み物（記事）
- 2026-11-07：**読み物を増やす順番を決めた。** 火事マップ → 糸魚川大火 → 火事が多い月・曜日・時間帯 →（ここまで公開済み）→ 火災警報器の交換時期チェッカー → 消防車図鑑 → 備えチェック10問 → 酒田大火・函館大火 → 大火の一覧。理由は `seo/decisions.md` の同じ日付を参照。
- 2026-11-08（PR #14）：**記事の先頭の画像は、写真AC・イラストACのフリー素材を使う。複雑なイラストは自作しない。** 理由：自作の消防車のイラストの出来がよくなかったため。自作するのは棒グラフ・手順図などの簡単な図解だけ。
- 2026-11-08：**素材の候補は、先に運営者へ見せてから決める。** 理由：サイトの雰囲気に影響するため。
- 2026-11-08：**実在の火災現場・被災者が写った写真は使わない。**
- 2026-11-09（PR #17）：**画像に「写真AC」「イラストAC」の出典表記は入れない。** 理由：規約上は不要なため（運営者の判断）。どの素材を使ったかは `site/guides.py` の `PHOTOS` と PR に残す。
- 2026-11-07：**火事マップは1ページだけにする。** 都道府県・市区町村ごとの地図ページは作らない。理由：都道府県ページと内容が重なり、似たページの大量生成になるため。絞り込みは URL の `#` で行う。
- 2026-11-07：**過去の大火の記事は、被害者名・店名・凄惨な描写を扱わない。出典は国・自治体の報告書にする。**

## トップページの見せ方
- 2026-11-09（PR #18・#19）：**「いま・直近24時間の火事」は、日時を左に大きく出し、最初は6件だけ見せて残りはボタンで開く。** 理由：利用者が見たいのは「いつ・どこで」なのに日時が見づらく、件数が多い日はページが縦に長くなっていたため。

## SEO（詳しくは `seo/decisions.md`）
- 2026-11-06：**SEO の判断は SEO 担当（`.claude/agents/seo.md`）に任せる。** 理由：ほかの作業と文脈が混ざらないようにするため。Search Console のデータは GitHub Actions で毎日自動で取る。
- 2026-11-11：**当面は、読み物の追加より、Google への登録の対策を先にする。** 理由：登録されているのがトップ1ページだけのため。
- 2026-11-11（PR #21）：**消えたページは、同じ火事・町・市区町村のページへ自動で移す（0秒の meta refresh ＋ canonical）。`noindex` は付けない。行き先がないものは 404 にする。移動ページは1年で消す。** 理由：トップへまとめて送るとソフト404扱いになりうるため。`noindex` は「移動先へまとめる」という合図と食い違うため。
- 2026-11-11（PR #21）：**サイトマップの更新日は、題名・説明文・本文が変わった日にする。** 理由：フッターの取得時刻のせいで全ページの更新日が毎日「今日」になっており、Google に信用されない状態だったため。
- 2026-11-11（PR #21・#22）：**サイトマップに載せるページを絞る。** 90日より古い火事のページ、記録も案内ダイヤルもない市区町村、記録が1件だけで90日より古い町、町単位の記録がない23区の町を外す。ページ自体は残し、`noindex` も付けない。理由：Google のクロールが週18回しかなく、先に見てほしいページへ寄せるため。
- 2026-11-11（PR #22）：**サイトマップを型ごとの6ファイルに分ける。** 理由：Search Console で、どの型が登録されていないかを見るため。
- 2026-11-11（PR #22）：**IndexNow（Bing など）は、公開のあとに送る。今日変わったページも送る。** 理由：公開前に送ると、Bing がまだないページを取りに来るため。
- 2026-11-11：**外からの入口は、費用のかからないものから進める。** X の投稿 → note・Zenn の記事 → プロフィールからのリンクの順。相互リンクの依頼や、リンク集への大量登録はしない。
