# 火事速（kajisoku.jp）（全国版）

23区だけの版は `backup-23ku` ブランチに保存。

「今どこで火事？」を地名で確かめるサイト。近所の人の目撃報告（サイレン／煙・におい／火）と口コミ、報道を、全国の都道府県・市区町村（1,898）・町（約12万）ごとにリアルタイムでまとめる。東京23区は東京消防庁の公開データで消防署ごとの火災件数と926町のページも持つ。

## 全国版のデータ
- `data/raw/areas.json` … 都道府県・市区町村（政令市は区）と地方公共団体コード、読み。総務省「全国地方公共団体コード」（nojimage/local-gov-code-jp のJSON化）
- `data/raw/towns_jp.json` … 全国の町名（丁目を除く）と代表点の位置。Geolonia 住所データ（CC BY 4.0）から作成。浜松市は2024年の区の再編に合わせて付け替え
- `data/raw/news_archive.json` … 報道から取り出した火事の場所と日付（全期間）。検索候補の「○件」に使う
- 検索は `dist/s/*.js`（町名を2文字ごとに512分割した索引）、町の位置は `dist/t/<コード>.js`。どちらもサーバーなしで動く

## 仕組み
1. `collector/run.mjs` … 東京消防庁サイトから収集（23区の管轄表 → 58署の災害情報ページ → 日次速報）。解析は `parse_station.js`（署ごとに違う表の書式を見出しで読み分け、読み取った行も記録）。
2. `site/build.py` … `data/raw/` の最新データからページを生成（`dist/`）。トップ（町名検索・現在地・いまの火事）、町ページ926（渋谷区・目黒区の町名は `towns_extra.json`）、火事のページ、区ページ、統計、投稿ルール。
3. `site/og.js` … SNS共有用のOGP画像（区ごと・読み物・火事マップ）。
   - `site/mapview.py` … 火事マップ `map.html`。直近30日の記録を町の代表点に置いた `dist/data/map.json` と、近所の人の報告に位置をつけるための都道府県ごとの町の代表点 `dist/data/geo/NN.json` を作る。地図の動きは `site/assets/map.js`（Leaflet＋国土地理院タイル、`#p=都道府県&d=7` で絞り込み）
4. `site/verify.js` … 自動チェック（出典行と値の一致、区の合計の再計算、人口の検算、表示エラー・横はみ出し・リンク切れ・検索・並べ替え）。
5. `site/verify_live.mjs` … 公開前に、全署の公式ページを取り直して値を再照合。
6. `collector/news_run.mjs` … 報道（Googleニュースの検索RSS 74本：全国・47都道府県・23区）から全国の火事を抽出（`news_jp.js`、テストは `news_jp.test.mjs`）し `data/raw/news.json` に30日分を保持。見出し文は保存・表示せず、区・町名・建物の種類・けが人の有無・報道元リンクだけを使う（`news.js`）。
7. `worker/` … 目撃報告・口コミの受付サーバー（Cloudflare Workers + D1）。
   - 同じ町・2時間以内の報告を1つの「火事」にまとめ、`fire.html?id=` で火事のページを表示。
   - 口コミは火事ごと・町ごとに投稿可。URL・電話番号・番地・中傷は受け付けず、3人の通報で非表示。削除依頼は `contact` 表に入る（D1 のコンソールで確認）。
   - `/f/<火事ID>` は共有用。X・LINE に貼ると「北区赤羽西2丁目付近で火事の目撃情報 5件」のような見出しが出る。
   - IPは日替わりの塩付きハッシュでのみ使用（連投制限）。`node worker/test.mjs` で動作テスト。
8. `.github/workflows/daily.yml` … 毎朝すべて、30分ごとに報道だけを取り直して生成・検査し、GitHub Pages に公開。

## 「いまの火事」の情報源（kaji.news と同じ考え方）
東京消防庁の災害情報案内（03-3212-2119）は職員が応対する窓口のため、自動発信はしない。代わりに
- 報道（上記6）… 23区の火事で、けが人や大きな被害があるものはほぼ報道される
- 利用者の報告（上記7）… 「サイレンが聞こえた／煙／火」をワンタップで。近くの人の報告が集まると、その区・町に件数が出る
を組み合わせる。多摩地区・他県に広げるときは、録音で案内している消防本部の災害案内ダイヤル（自動発信＋文字起こし）や、市のメール配信（すぐメール等）を加える。

## 受付サーバーの公開
Cloudflare の Workers & Pages で、このリポジトリを「GitHub から取り込み」済み（ルートディレクトリ `worker`）。`main` に push すると Cloudflare 側で自動公開される。
データベース（D1 `kaji23`）の表とハッシュ用の塩は、受付サーバーが初回アクセス時に自動で作る。秘密鍵の登録は不要。
公開先URLを `worker/url.txt` に書くと、次のサイト生成からボタンがそこへ送信する。

## 手動で動かす
```
npm ci
node collector/run.mjs          # 収集
cd site && ./run_all.sh          # 生成・検査（Playwright が必要）
```
独自ドメインを使うときは `SITE_URL=https://example.jp ./run_all.sh`（OGP・シェアのURLに使われます）。

## データの更新頻度
- 署ページ：署ごとに不定期（毎日〜月1回）。集計時点はページごとに表示。
- 報道：30分ごと。
- サイレン報告：リアルタイム（ページは1分ごとに集計を取り直す）。
- 人口：年1回（1月1日現在）。`data/raw/pop_YYYY-01-01.json` を東京都の統計 第1表CSVから更新。

## 全国展開の手順
`collect_tfd.js` の区・署のリストと探索ルールを、各消防本部のサイト構成に合わせた「取得アダプタ」として追加する。`parse_station.js` の表の読み分けはそのまま使える。

## 消防本部の出動情報
- 受付サーバーが5分ごとに `worker/src/official.js` の一覧のページを読み、火災の出動だけを取り込む（robots.txt を守る）。
- 状況確認: `https://kaji23-reports.kinde-32795.workers.dev/api/sources`（`?debug=1` で各ページの「火災・出動を含む行」の見本）。
- 追加: 一覧に1行足す。日時・場所・種別が1行に書かれた文章形式ならそのまま読める。時刻のない「出動中」だけのページは `current: true`。
- 京都市は海外からの接続を受け付けていないようで読めない（HTTP 522）。

## 運用・公開前にやること
- 独自ドメインを取得 → GitHub の Settings → Pages で設定し、Variables に `SITE_URL` を登録（正規URL・共有URL・サイトマップが切り替わる）。受付サーバーの `ALLOW_ORIGIN` もそのドメインに。
- Google Search Console に登録して `sitemap.xml` を送信（独自ドメイン後）。
- `policy.html` の運営者名・連絡先: Variables に `SITE_OPERATOR`・`SITE_CONTACT` を登録。
- 監視: 毎回の自動チェックで受付サーバーの応答・消防ページの読み取り・報道の鮮度を確認。失敗すると GitHub からメールが届く。
